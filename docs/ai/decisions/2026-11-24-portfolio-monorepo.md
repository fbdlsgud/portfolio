# 포트폴리오 모노레포

## 상태

채택

## 배경

React 프론트엔드와 Spring Boot API는 같은 도메인과 배포 주기를 공유한다. Mac mini에서 두 앱을 함께 운영한다.

## 검토

- 저장소를 두 개 유지하면 각 저장소에서 별도로 변경을 기록할 수 있지만 API 변경과 배포 구성을 함께 검토하기 어렵다.
- 하나로 통합하면 API와 프론트 변경을 한 커밋에서 검토할 수 있고 기존 npm·Gradle 빌드 경계를 유지할 수 있다.

## 결정

기존 `fbdlsgud/portfolio` 저장소에 `frontend/`, `backend/`, `deploy/`를 둔다. 프론트 파일은 Git 이동으로 기록하고 백엔드 원본 커밋은 Git subtree 병합으로 가져온다. 두 앱은 Docker에서 개별 이미지로 빌드하며 MySQL 운영 볼륨과 Cloudflare Tunnel은 기존 구성에 연결한다.

## 검증

양쪽 원본 커밋이 통합 브랜치의 조상이고 앱 소스가 원본과 동일한지 확인한다. 격리된 Compose 프로젝트로 화면과 API를 검증하고 운영 반영 시 MySQL 컨테이너와 볼륨이 유지되는지 비교한다.
